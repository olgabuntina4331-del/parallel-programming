# parallel-programming
Polynomial least squares approximation using C++ and OpenMP

### постановка задачи

задан набор точек и значения функции в этих точках. требуется с помощью метода наименьших квадратов найти полиномиальную функцию степени не выше третьей, максимально приближающую исходные данные

### алгоритм

Искомый полином имеет вид:

$$
P_m(x)=a_0+a_1x+\ldots+a_mx^m,\quad 0\le m\le3
$$

коэффициенты определяются минимизацией суммы квадратов ошибок:

$$
S=\sum_{i=1}^{n}(y_i-P_m(x_i))^2
$$

алгоритм:

1. считываем исходные точки из текстового файла
2. вычисляем суммы, необходимые для построения сист. норм. ур-й
3. решаем системы гауссом с выбором ведущей строки
4. вычисляем суммы квадратов ошибок для полиномов допустимых степеней
5. выбираем полином с наименьшей ошибкой. при практически одинаковой ошибке выбираем полином меньшей степени

### использование OpenMP и запуск

параллельные вычисления реализованы в двух функциях:

- `calculateSums()` — параллельное вычисление сумм для нормальных уравнений
- `squaredError()` — параллельное вычисление суммы квадратов ошибок

используются директивы `#pragma omp parallel for` с операцией `reduction`

программа написана на C++17 и использует OpenMP. компиляция в GitHub Codespaces:

```bash
g++ -std=c++17 -O2 -fopenmp mnk.cpp -o mnk
```

запуск:

```bash
./mnk
```

программа считывает исходные точки из файла `points_100000.txt`. для изменения набора данных необходимо поменять название входного файла в функции `main()` и повторно скомпилировать программу

### результат

для набора из 100 000 точек получен полином третьей степени:

$$
P(x)=2.005980-1.499124x+0.749875x^2-0.100013x^3
$$

сумма квадратов ошибок:

$$
SSE=64334.716373
$$

### исследование производительности OpenMP

для оценки эффективности параллельных вычислений провела эксперимент на наборе из 100 000 точек

программа запускалась с 1, 2 и 4 потоками OpenMP. для каждой конфигурации выполнено пять измерений. для сравнения использовалась медиана времени выполнения

### результаты эксперимента

| количество потоков | медианное время, с | ускорение |
|---|---|---|
| 1 | 0.001426484 | 1.00 |
| 2 | 0.001711242 | 0.83 |
| 4 | 0.001968347 | 0.72 |

ускорение вычислялось по формуле:

$$S_p = \frac{T_1}{T_p},$$

где $T_1$ — время выполнения с одним потоком, а $T_p$ — время выполнения с $p$ потоками

### анализ результатов

по результатам повторных измерений наименьшее время выполнения получено при использовании одного потока. при увеличении количества потоков до двух и четырёх время выполнения возрастает. скорее всего это связано с небольшим объёмом вычислений, накладными расходами на параллелизацию и синхронизацию потоков, а также особенностями виртуальной среды GitHub Codespaces. т к время выполнения всего несколько миллисекунд, влияние накладных расходов оказывается большим

### вывод

реализована параллельная версия метода наименьших квадратов с использованием OpenMP. корректность полученного полинома подтверждена тестовыми данными. измерения показали, что увеличение количества потоков не всегда приводит к ускорению программы.на наборе из 100 000 точек наиболее быстрое выполнение обеспечила конфигурация с одним потоком.
